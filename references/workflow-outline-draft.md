# Outline and Draft Workflow

## Build the outline from claims

Before full prose, establish:

1. one-sentence paper thesis;
2. target venue, paper type, audience, and maturity;
3. problem-gap-question-method-evidence-significance chain;
4. each section's unique responsibility;
5. move-level and paragraph-level argument map;
6. claim-evidence ledger;
7. open dependencies and claims prohibited by current evidence;
8. venue/template and literature-verification work still required.

An outline should contain proposed controlling claims and evidence, not only section headings.

## Draft in dependency order

Drafting order need not equal reading order. Prefer:

1. stabilize Problem Setup, method target, and experimental questions;
2. draft Methods and evaluation protocol from artifacts;
3. draft Results only from audited outputs;
4. draft Discussion and limitations from bounded findings;
5. finalize Introduction, Contributions, Abstract, Title, and Conclusion after the evidence is stable.

For a conceptual proposal or partially complete paper, create structurally valid placeholders in source comments or an explicit planning document. Do not write planned results as if observed.

When Results are still planned, the safe deliverable may contain only:

- research-question or hypothesis headings;
- metric and comparison definitions;
- table/figure schemas with explicit `TBD` cells;
- expected result-artifact paths or locators;
- predeclared interpretation and decision rules;
- dependencies required before prose can be completed.

Do not insert plausible numbers, directional findings, significance language, or conclusion-shaped sentences. Keep the analysis plan in Methods or Protocol; keep the Results skeleton visibly incomplete.

## Draft paragraphs from controlling functions

1. Write one controlling sentence or formal statement per planned paragraph.
2. Read the sequence alone and test whether it forms a complete, non-redundant argument.
3. Add definitions, evidence, examples, equations, citations, qualifiers, and implications.
4. Add transitions based on the actual relation between claims.
5. Run deletion, one-function, known-new, and dependency tests.

Do not force the controlling sentence to be the same grammatical form in every paragraph. Clarity of function matters more than surface uniformity.

## Preserve provenance while drafting

- Attach each numerical result to a table, log, analysis file, or audited report.
- Attach each external claim to a verified source and exact support location.
- Keep theorem statements synchronized with proof assumptions.
- Use source comments for unresolved claims and remove or resolve them before submission.
- Preserve citation keys and technical terms already defined by the project unless correction is justified.

## Fit the page or word budget intelligently

Shorten in this order:

1. remove redundancy and throat-clearing;
2. merge moves that remain clear together;
3. replace catalogues with synthesis;
4. move secondary detail to an allowed supplement;
5. narrow claims and scope if essential evidence cannot fit.

Never compress by deleting definitions, critical controls, uncertainty, or limitations necessary to judge the main claim. Never alter the official template.
